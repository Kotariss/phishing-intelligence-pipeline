# Phishing Intelligence Pipeline (DW-2)

Прототип системы глубокого анализа фишинговых веб-страниц и вложений и обобщения его результатов в компактные
признаки для локальной антиспам-фильтрации. Принимает письма EML, URL, сохранённые HTML-страницы со снимками экрана,
вложения и изображения с QR-кодами; разбирает их в изолированной песочнице, оценивает мультиагентным конвейером
(структурные экстракторы + LLM/VLM), объясняет вердикт кодами причин с уликами и превращает найденное в пакет артефактов
(сигнатуры, правила, YARA) для лёгкого модуля антиспам-движка.

Результат не сводится к списку заблокированных URL: правила описывают **технику** (имитация бренда + форма сбора данных,
канал эксфильтрации, загрузка нагрузки, HTML-вложение, подмена отправителя) и переносятся на смену доменов и URL.
Каждое правило до включения в пакет проверяется на наборе заведомо легитимных объектов (Zero FPR Guard).

## Архитектура

```
образец: EML / URL / HTML + скриншот / вложение / изображение      клиенты: CLI · REST API · UI
                              │                                              │
                              ▼                                              ▼
                ┌───────────────────────────┐   HTTP    ┌──────────────────────────────┐
                │  sandbox        :8001     │◄──────────│  worker               :8000  │
                │  разбор и рендер опасных  │  (только  │  агенты LangGraph, база      │
                │  объектов, без интернета  │  sandbox_ │  знаний, Zero FPR Guard,     │
                └───────────────────────────┘  net)     │  правила, пакет артефактов   │
                                                        └───────┬──────────────┬───────┘
                                                  SQL           │              │ OpenAI-совместимый API
                                                                ▼              ▼
                                                  ┌──────────────────┐  ┌────────────────────┐
                                                  │ db     :5432     │  │ llm      :11434    │
                                                  │ PostgreSQL 16    │  │ Ollama (Qwen),     │
                                                  │ (или SQLite)     │  │ без интернета      │
                                                  └──────────────────┘  └────────────────────┘
```

Конвейер (граф LangGraph в `worker`):
`triage` (песочница / собранные артефакты) → `url` (редиректы, домены-двойники, омографы, IP, бесплатный хостинг,
нагрузки) → `dom` (формы и адреса отправки, пароли и карты, эксфильтрация, обфускация, антианализ, остов DOM) →
`vision` (бренд: отправитель, заголовок, VLM, домен-двойник; проверка «бренд — домен») → `quishing` (вложения, QR,
макросы, PDF, архивы, заголовки письма) → `content` (LLM-анализ текста приманки) → `aggregator` (второй проход по
ссылке из письма / QR) → `synthesizer` (риск, составные признаки, Level-1 allowlist, правила, отпечатки, кампания,
пояснение) → `persist`.

### Вердикт

Риск = noisy-OR по независимым уликам `1 − Π(1 − wᵢ)` (веса — в [каталоге кодов причин](docs/REASON_CODES.md)):
`< 0.30` — признаков фишинга не обнаружено, `0.30–0.70` — подозрительно, `≥ 0.70` — фишинг. LLM/VLM не выносят
вердикт сами, а добавляют улики с кодами причин; решение считает формула. Если финальная страница находится на
официальном домене бренда, признаки самой страницы нейтрализуются, а улики письма и вложений сохраняются (переход
со стороннего домена на официальный фиксируется как клоакинг).

### Режимы модели

Тексты приманок, изображения и бренды оценивает LLM/VLM; структурные экстракторы готовят ей данные. Объект, на котором
модель не ответила после всех попыток (`LLM_ATTEMPTS`), получает статус `skipped_llm`: он не оценивается без модели, а
учитывается в отчёте о полноте обработки.

| `LLM_MODE` | Подключение | Модели |
|---|---|---|
| `local` | в Docker — контейнер `llm` (Ollama) во внутренней сети без выхода в интернет; вне Docker — Ollama / LM Studio / vLLM по `LLM_LOCAL_BASE_URL` | `LLM_LOCAL_TEXT_MODEL`, `LLM_LOCAL_VISION_MODEL` (по умолчанию `qwen3-vl:2b-instruct`) |
| `cloud` | удалённый OpenAI-совместимый сервер: `LLM_CLOUD_BASE_URL` + `LLM_CLOUD_API_KEY` | `LLM_CLOUD_TEXT_MODEL`, `LLM_CLOUD_VISION_MODEL` |

Данные Заказчика обрабатываются только в режиме `local` (ТЗ 4.4.2, 4.5.2.2). Модели один раз скачивает контейнер
`llm-init` в том `llm_models` (единственный шаг, которому нужен интернет); при уже скачанных моделях система работает
полностью офлайн. Режим переключается без пересборки: `LLM_MODE=local docker compose up -d worker`.
Промпты — в `services/worker/src/prompts/`, подробности — в [docs/LLM_AND_PROMPTS.md](docs/LLM_AND_PROMPTS.md).

## Быстрый старт

### Требования

- Linux x86-64, Docker и Docker Compose v2 (запуск в контейнерах); 4 ядра CPU, 8 ГБ ОЗУ, 15 ГБ на диске.
- Python 3.10+ (локальный запуск и тесты).
- GPU с 8 ГБ видеопамяти — для локальной LLM/VLM; без GPU модель работает на CPU заметно медленнее.
- Интернет — только один раз, для загрузки образов и моделей Ollama.
- Данные Заказчика — каталог `file_for_case/` в корне репозитория (в git не входит). Он содержит вредоносные файлы:
  добавьте его в исключения антивируса и не открывайте HTML в браузере.

### Конфигурация

Скопируйте файл-образец и при необходимости измените значения (`.env` в репозиторий не входит):

```bash
cp .env.example .env
```

| Переменная | Обязательная | По умолчанию | Описание |
|---|---|---|---|
| `LLM_MODE` | да | `local` | `local` — своя модель без внешней сети, `cloud` — удалённый сервер |
| `LLM_LOCAL_BASE_URL` | local | `http://localhost:11434/v1` | адрес OpenAI-совместимого сервера (в Docker подставляется `http://llm:11434/v1`) |
| `LLM_LOCAL_TEXT_MODEL`, `LLM_LOCAL_VISION_MODEL` | local | `qwen3-vl:2b-instruct` | модели текста и изображений |
| `LLM_CLOUD_BASE_URL`, `LLM_CLOUD_API_KEY`, `LLM_CLOUD_TEXT_MODEL`, `LLM_CLOUD_VISION_MODEL` | cloud | — | параметры удалённого сервера |
| `LLM_ATTEMPTS` | нет | `4` | число попыток вызова модели (паузы 2, 5, 10 с), затем объект получает `skipped_llm` |
| `LLM_TIMEOUT_SECONDS`, `LLM_TEMPERATURE`, `LLM_MAX_TOKENS`, `LLM_REASONING_EFFORT` | нет | `180`, `0.1`, `4000`, пусто | параметры вызова модели |
| `DATABASE_URL` | нет | `sqlite:///./pipeline.db` | база знаний; в Docker подменяется PostgreSQL |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | нет | `phish_user`, `change_me`, `phishing_db` | PostgreSQL в Docker (смените пароль) |
| `SANDBOX_HOST`, `SANDBOX_PORT` | нет | `localhost`, `8001` | адрес песочницы |
| `SANDBOX_INPROCESS_FALLBACK` | нет | `true` локально | разбор в процессе worker без контейнера песочницы; в Docker запрещён |
| `SANDBOX_TIMEOUT_SECONDS`, `SANDBOX_MAX_REDIRECTS`, `SANDBOX_MAX_FILE_SIZE_MB`, `ANTI_SSRF_ENABLED` | нет | `10`, `10`, `25`, `true` | лимиты и защита песочницы |
| `SCORE_CLEAN_THRESHOLD`, `SCORE_MALICIOUS_THRESHOLD` | нет | `0.30`, `0.70` | пороги вердикта |

> Если в `.env` указано `LLM_MODE=cloud`, `docker compose up` отправит содержимое объектов на удалённый сервер.
> Для данных Заказчика используйте `LLM_MODE=local`.

### Запуск

В Docker (рекомендуется):

```bash
# Сборка образов
docker compose build

# Запуск всей системы (первый запуск скачивает модели Ollama — нужен интернет)
docker compose up -d
```

API: `http://localhost:8000` (Swagger: `/docs`), интерфейс аналитика: `http://localhost:8501`.
Проверка: `curl http://localhost:8000/health` — поле `llm_ready` должно быть `true`.

Локально (без контейнеров):

```bash
pip install -r services/worker/requirements.txt -r services/sandbox/requirements.txt -r services/ui/requirements.txt
python phishctl.py analyze "file_for_case/keis2/Adobe/bfc7879dc6f69c94cc86b74f3158ee30033bd12f"
python -m streamlit run services/ui/app.py
```

### Запуск отдельных компонентов

```bash
# Только песочница и база знаний (API и CLI запускаются на хосте)
docker compose up -d sandbox db

# Песочница с выходом в сеть для активного раскрытия URL (расширенная версия)
docker compose --profile live-fetch up -d
```

### Остановка

```bash
docker compose down        # остановить; база знаний и модели сохраняются в томах
docker compose down -v     # остановить и удалить тома (база знаний и скачанные модели)
```

Контейнеры перезапускаются автоматически (`restart: unless-stopped`); после отказа достаточно повторного
`docker compose up -d`, сохранённые результаты не теряются.

## Интерфейс командной строки

```bash
python phishctl.py --help
```

| Команда | Назначение |
|---|---|
| `import-corpus <dir>` | индекс корпуса: тип, размер, SHA-256, дубликаты, происхождение → `reports/corpus_index.json` |
| `analyze <файл \| каталог образца \| URL> [--json out.json] [--online]` | анализ одного объекта; список URL (`.txt`, по одному на строку), ZIP-архив или каталог объектов запускаются пакетно, как `analyze-dir` |
| `analyze page.html --url <URL> [--screenshot shot.png]` | анализ сохранённой страницы со снимком экрана |
| `analyze-dir <dir \| .zip \| urls.txt> [--out reports/results.jsonl] [--limit N]` | пакетный анализ каталога, ZIP-архива (с защитой от выхода за каталог и лимитами) или списка URL; продолжает с места остановки, битые объекты не прерывают прогон; повторный объект помечается `duplicate_of` |
| `kb-stats` | статистика базы знаний, частота техник, бренды |
| `cluster [--min-size 2] [--visual]` | фишинговые кампании (общий kit / инфраструктура; `--visual` — по перцептивному хешу скриншота) |
| `export-package [--out exports/package]` | версионированный пакет артефактов (JSON + YARA) |
| `apply <package.json> <файлы/каталоги>` | применение пакета лёгким модулем (без тяжёлых экстракторов) |
| `split [--dev-share 0.3] [--seen-from FILE]` | разбиение корпуса на настройку / отложенную часть без утечек → `reports/split.json` |
| `metrics [--limit N] [--sources keis2,html,png] [--part dev\|test] [--workers N]` | метрики приёмки → `reports/metrics.json` |
| `eval-labeled <dir>` | оценка на размеченном наборе EML (`manifest.csv`) |
| `robustness [--limit N] [--part test]` | устойчивость: recall после замены домена / URL, смены оформления и отложенной загрузки |
| `diff-runs <A> <B> [--out F]` | сравнение двух прогонов по объектам: переходы вердиктов, появившиеся и исчезнувшие признаки |
| `build-benign-corpus` | пересборка признаков легитимного набора для Zero FPR Guard |

Глобальный флаг `--llm local|cloud` переопределяет режим модели для команды. Если модель не настроена, команда
сообщает, каких переменных не хватает.

## Тесты

```bash
python -m pytest tests -q                         # все тесты
python -m pytest tests/test_rule_compiler.py -q   # один файл
```

Тесты покрывают экстракторы, разбор вложений, безопасность песочницы (SSRF, в том числе через редиректы), реестр
брендов, генерацию и применение правил, YARA, политику вердиктов, легитимный набор, CLI, API и метрики. Они работают
офлайн: модель подменяется фикстурой `fake_llm` (`tests/conftest.py`), сеть не используется; тесты на файлах датасета
пропускаются, если `file_for_case/` отсутствует.

### Вспомогательные скрипты

## API

Интерактивная документация: `http://localhost:8000/docs`. Базовый адрес — `http://localhost:8000`.

### Анализ (`/api/v1/scan`)

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/v1/scan` | анализ объекта: `multipart/form-data` с полем `file` или `url` (http/https) |
| `POST` | `/api/v1/scan/snapshot` | сохранённая страница: `html` (файл), `url`, опционально `screenshot` |
| `POST` | `/api/v1/scan/sample` | образец датасета: `path` относительно `DATASET_DIR` (EML + собранные ссылки) |

```bash
curl -F "file=@sample.eml" http://localhost:8000/api/v1/scan
```

Ответ — JSON с вердиктом (`MALICIOUS` / `SUSPICIOUS` / `CLEAN`), риском, кодами причин с уликами, извлечёнными
признаками, пояснением на русском, отпечатками и правилом (если оно построено).

**Статусы ответа:**

| Код | Статус | Описание |
|---|---|---|
| 200 | OK | анализ выполнен |
| 400 | Bad Request | не передан ни `file`, ни `url`; адрес не http(s) |
| 413 | Payload Too Large | файл больше 25 МБ |
| 404 | Not Found | инцидент не найден (`GET /api/v1/incidents/{id}`) |
| 500 | Internal Server Error | ошибка конвейера (в `detail` — тип и сообщение) |
| 503 | Service Unavailable | модель не отвечает после всех попыток или не настроена |

### База знаний и пакет артефактов

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/health` | состояние сервиса, режим и готовность модели (`llm_ready`, `llm_problem`) |
| `GET` | `/api/v1/incidents?limit=&offset=&verdict=&brand=` | список инцидентов базы знаний |
| `GET` | `/api/v1/incidents/{id}` | результат анализа с уликами и отпечатками |
| `GET` | `/api/v1/campaigns?min_size=2` | кампании (инциденты с общим kit / инфраструктурой) |
| `GET` | `/api/v1/signatures` | реестр правил со статусами |
| `GET` | `/api/v1/stats` | статистика базы знаний |
| `GET` | `/api/v1/reason-codes` | каталог кодов причин |
| `POST` | `/api/v1/package` | сформировать новую версию пакета артефактов и вернуть его (JSON) |

## Логирование

- Журнал обращений к модели: `logs/llm_audit.jsonl` — объект, версия промпта, модель, полный промпт и ответ, число
  попыток, время; читаемая копия — `logs/llm_audit.log`; последние записи — `GET /api/v1/llm_audit`.
- Ход анализа каждого объекта: трассы агентов в результате (`agent_traces`: применённые экстракторы, промежуточные
  результаты, время каждого этапа); пакетные прогоны сохраняют сводку и диагностику по объектам (`diag`, раздел
  `diagnostics`) в JSON-отчёт `reports/*.json`.
- Ошибки разбора и рендера попадают в результат объекта (`status: error`, текст и трасса); при пакетной обработке они не
  прерывают прогон.
- Хранение: каталоги `logs/` и `reports/` монтируются в контейнеры и в git не входят.
- Токены и чувствительные параметры URL маскируются в отчётах и уликах (ТЗ 4.5.2.3).

## Сетевая конфигурация

Адреса назначает Docker; изоляция задана сетями (`docker-compose.yml`):

| Сеть | Тип | Участники |
|---|---|---|
| `sandbox_net` | internal (без выхода в интернет) | sandbox, worker (и `sandbox-online` в профиле `live-fetch`) |
| `llm_net` | internal (без выхода в интернет) | llm, worker |
| `backend_net` | bridge | db, worker, ui |
| `egress_net` | bridge (выход в интернет) | worker, llm-init (загрузка моделей), `sandbox-online` |

Порты 8000 и 8501 опубликованы только на `127.0.0.1` хоста.
