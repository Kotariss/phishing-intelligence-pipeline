# worker — агенты, база знаний, правила, REST API, CLI

Ядро системы. Принимает объект (письмо, URL, страница, файл), передаёт недоверенную часть в `sandbox`, прогоняет
мультиагентный конвейер LangGraph (структурные экстракторы + LLM/VLM), считает вердикт и объясняет его кодами причин,
сохраняет результат в базу знаний и формирует пакет артефактов для лёгкого антиспам-движка.

## Архитектура

```
вход (CLI / REST) ─► orchestrator/graph.py ─► triage ─► url ─► dom ─► vision ─► quishing ─► content ─► aggregator
                                                                                                         │
                       пакет артефактов ◄── rules/ ◄── db/ (база знаний) ◄── persist ◄── synthesizer ◄───┘
```

### Ключевые компоненты

**`src/orchestrator/` — `PhishingState`, граф**
Общее состояние расследования (улики, коды причин, трассы агентов) и граф LangGraph. Второй проход по ссылке из
письма или QR выполняется не более одного раза.

**`src/agents/`**
`triage` (песочница), `url`, `dom`, `vision` (бренд, VLM), `quishing` (вложения, QR, заголовки), `content` (LLM-анализ
текста приманки), `synthesizer` (noisy-OR риск, составные признаки, Level-1 allowlist, правила, пояснение). LLM/VLM
добавляют улики, но не выносят вердикт.

**`src/rules/`**
Каталог кодов причин с весами (`reason_codes.py`), компилятор правил «набор признаков → фишинг / подозрительно»
(`compiler.py`), Zero FPR Guard (`zero_fpr_guard.py`), YARA (`yara_gen.py`), версионированный пакет с происхождением
правил (`package.py`, `exporter.py`), лёгкий модуль применения пакета без тяжёлых экстракторов (`light_engine.py`).

**`src/brands/`**
Реестр из 175 целевых брендов (названия, легитимные домены, связи) и сопоставление: отправитель, заголовок, омографы
и двойники домена.

**`src/features/`, `src/ingest/`**
Признаки URL и отпечатки (SHA-256, остов DOM, перцептивный хеш скриншота); загрузка датасета Заказчика.

**`src/db/`**
База знаний: объекты и происхождение, признаки, индикаторы, отпечатки, бренды, кампании, правила (SQLite или
PostgreSQL). Схема — [docs/KNOWLEDGE_BASE_AND_FORMATS.md](../../docs/KNOWLEDGE_BASE_AND_FORMATS.md).

**`src/llm/`, `src/prompts/`**
Клиент OpenAI-совместимого сервера (повторы, аудит каждого вызова) и версионируемые промпты. Если модель не отвечает
после `LLM_ATTEMPTS` попыток, объект получает `skipped_llm`.

**`src/evaluation.py`, `src/cli.py`, `src/main.py`**
Расчёт метрик и устойчивости, командная строка, REST API.

## Быстрый старт

### Требования

- Python 3.10+, зависимости `requirements.txt`; запущенная `sandbox` (или `SANDBOX_INPROCESS_FALLBACK=true` для
  локальной разработки); LLM/VLM-сервер по `LLM_MODE`.

### Конфигурация

Переменные описаны в [корневом README](../../README.md#конфигурация); файл-образец — `.env.example`.

### Запуск

```bash
docker compose up -d worker        # вместе с sandbox, db, llm
uvicorn src.main:app --port 8000   # локально, из services/worker
python phishctl.py --help          # CLI из корня репозитория
```

### Остановка

```bash
docker compose stop worker
```

## Тесты

```bash
python -m pytest tests -q
```

Модель в тестах подменяет фикстура `fake_llm`; сеть не используется.

## API

Описание методов — в [корневом README](../../README.md#api); интерактивная документация — `http://localhost:8000/docs`.

## Логирование

Журнал обращений к модели — `logs/llm_audit.jsonl` и `GET /api/v1/llm_audit`; трассы агентов (`agent_traces`) входят в
результат каждого объекта; пакетные прогоны пишут сводку и диагностику в `reports/*.json`.
