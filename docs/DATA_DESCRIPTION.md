# Описание данных

Состав корпуса Заказчика, базы целевых брендов, легитимного набора, размеченных выборок и разбиения на части настройки и
оценки (ТЗ, табл. 7). Данные Заказчика в репозиторий не входят: они лежат в каталоге `file_for_case/` (исключён из git, ТЗ 4.5.2.2).
Все описанные ниже файлы воспроизводятся командами CLI; версии и хеши фиксируются в блоке `reproducibility` отчётов о метриках
(ТЗ 4.1.8.3).

## 1. Корпус Заказчика

Корпус содержит только фишинговые объекты (метка «фишинг»). Объём каталога — ≈ 1,6 ГБ; индекс (тип, размер, SHA-256, дубликаты,
происхождение) формирует `phishctl.py import-corpus file_for_case` → `reports/corpus_index.json`.

| Источник | Каталог | Объектов | Содержимое | Группа для разбиения |
|---|---|---|---|---|
| Письма целевых брендов | `keis2/<бренд>/<id>/` | 371 | письмо EML без расширения и собранные артефакты ссылок `Link_N` (цепочка перенаправлений, HTML, снимок экрана); 175 папок брендов | папка бренда |
| HTML-вложения | `html_phishing2026/` | 7 642 | сохранённые HTML-страницы и вложения фишинговых писем | хеш остова DOM (последовательность первых 600 тегов) |
| Изображения-приманки | `grouped_png_phishing2026/` | 2 854 | PNG-скриншоты фальшивых форм входа и «защищённых документов»; 42 каталога — кластеры Заказчика, `noise` (709 файлов) — без кластера | кластер; файлы `noise` — каждый сам по себе |
| Описание | `Пояснения_к_данным_для_кейса_2.pdf` | — | пояснения Заказчика к данным | — |

Особенности (ТЗ А.1.4): преобладание отдельных шаблонов завышает метрики по объектам — в части настройки есть шаблон из 2 267 копий
одного набора. Поэтому ТЗ требует разбиение по DOM-шаблонам, а метрики приводятся и по объектам, и по шаблонам. Цепочки
перенаправлений и внешние ресурсы недоступны офлайн: анализ идёт по сохранённым данным.

## 2. Разбиение на выборки (без утечек)

Команда `phishctl.py split --seen-from reports/seen_objects.txt` → манифест `reports/split.json` (назначение каждого объекта,
версия, доля, группировка). Делятся группы, а не объекты; назначение детерминировано (sha256 ключа группы).

| Источник | Часть настройки: объектов / групп | Отложенная часть: объектов / групп |
|---|---|---|
| письма keis2 | 331 / 146 | 40 / 26 |
| HTML-вложения | 6 204 / 378 | 1 438 / 675 |
| изображения | 1 276 / 231 | 1 578 / 519 |
| **Всего** | **7 811** | **3 056** |

Доля части настройки — 0,3 по группам; 1 346 объектов, просматривавшихся при разработке (`reports/seen_objects.txt`), принудительно отнесены
к части настройки вместе со своими группами. Признаки и веса настраиваются только на части настройки; отложенная часть даёт итоговые
цифры. Индикаторы кампаний (имена файлов, адреса) в оценку recall не входят.

## 3. База целевых брендов

Файл `services/worker/src/brands/brand_registry.json` — 175 брендов (по числу папок `keis2`), генерируется
`scripts/generate_brand_registry.py`. Поля записи: `brand_id`, `raw_dir_name` (имя папки корпуса), `display_name`, `category`
(122 `general`, остальные — облачные, технологические, логистика, финансы, криптовалюты, государственные, банки ЕС и др.),
`aliases` (написания на разных языках), `official_domains`, `allowed_domain_patterns` (регулярные выражения легитимных доменов),
`common_lures` (типичные приманки), связи между брендами (дочерние / партнёрские домены). Легитимные домены собраны Разработчиком
(ТЗ 4.1.2.2). Эталонные значки сайтов собраны с официальных доменов брендов (`scripts/collect_brand_icons.py` → `brands/icons/<brand_id>.png`,
`brand_icons.json` с перцептивным хешем; для 141 из 175 брендов, у остальных значок не отдаётся или слишком прост); значок на странице
(встроенный `data:`-favicon) сопоставляется с эталоном по хешу. Эталонных логотипов (крупных изображений) нет: бренд по логотипу
на снимке определяет VLM.

## 4. Легитимный набор

Файл `tests/fixtures/benign_samples.py` (проверка правил Zero FPR Guard и оценка ложных срабатываний), **34 синтетических объекта**,
собранных Разработчиком: 18 сохранённых страниц (страницы входа брендов на официальных доменах, агрегатор банков с формой входа,
чекаут магазина с логотипами платёжных систем, корпоративный SSO, дочерние компании брендов), 10 писем (рассылки брендов, счёт с PDF,
личная переписка), 6 изображений (баннер, чек, скан счёта, приглашение Teams, инструкция с формой входа). Признаки набора сохранены в
`services/worker/src/rules/benign_corpus.json` (`phishctl.py build-benign-corpus`).

**Ограничения.** Набор синтетический и писался вместе с правилами: «0 ложных» на нём — проверка согласованности, а не независимая оценка
(внутренний аудит метрик, A2–A3). Независимая оценка ложных срабатываний — на 500 легитимных письмах набора из п. 5.

### Реальные легитимные страницы брендов (локальный набор)

`scripts/collect_legit_pages.py` собирает с официальных доменов брендов реестра их главные страницы и страницы входа:
**159 страниц 129 брендов** (`file_for_case/legit_real/`, в репозиторий не входят: это сторонний контент). Набор не писался вместе с правилами,
поэтому служит независимой оценкой ложных срабатываний (ТЗ 4.1.2.3, табл. 3); команда `phishctl.py legit-eval`. Результат на структурном
режиме (без модели): 0 «фишинг», 5 «подозрительно» (3,1 %) из-за кода «текст ссылки не совпадает с адресом» на главных страницах Adobe,
gov.uk, SoftBank, UPS; после того как этот код стал нейтрализоваться на официальном домене бренда — 0 и 0 (правка сделана после просмотра
этих пяти страниц, поэтому итог помечается «после разбора ошибок»). Замеры с моделью — в `docs/METRICS.md`.

## 5. Размеченный набор писем (540)

Каталог `file_for_case/antiphishing_eml_540_combined/`: 40 фишинговых и 500 легитимных реальных писем (`manifest.csv`: `id`, `label`,
`subset`, язык, бренд, группа, основание метки; метка `corpus_publisher_label` / `public_mailing_list_context` — независимой проверки нет;
`compare_labels.py` — штатный расчёт метрик набора). Набор не использовался при настройке; оценка — `phishctl.py eval-labeled`.
Часть цифр после разбора ошибок помечена в `docs/METRICS.md` как не независимая.

## 6. Выборка с ручной эталонной разметкой (ТЗ табл. 3, ПМИ К-2)

Файл разметки (передаётся комиссии отдельно, в открытый репозиторий не включён: содержит адреса из корпуса Заказчика): 46 объектов отложенной части (25 HTML-вложений, 10 писем keis2, 11 изображений), 92 элемента —
ссылки (31), встроенные ресурсы (37), формы (14), адреса отправки данных и запросов сценария (8), вложения (1), QR-коды (1). Разметка
выполнена чтением исходного содержимого объектов, не выходом экстракторов; в файле записаны правило отбора и правило сопоставления
извлечённого элемента с эталонным (утверждаются комиссией до прогона). Токены и вебхуки корпуса в файле замаскированы.
